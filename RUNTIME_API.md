# Splinely runtime / export contract — v1

Implemented in `runtime/src/splinely.js` (no dependencies, no fetches). Read `runtime/README.md` for examples and precise transport rules. Schema compatibility was checked against `CORE_API.md` and `crates/splinely_document/src/{model,animation,behavior}.rs`.

## Export integration

Embed the **entire file unchanged** in a root SVG `<script>` after the node elements and project metadata. Auto-mount finds `document.currentScript.ownerSVGElement` and reads its options from the root `<svg>`: `data-splinely-max-fps="N"` (N > 0, as `maxFps`) and `data-splinely-native-animations="false"` (as `nativeAnimations: false`); other values keep the defaults. Root API: `svg.splinely`; `window.splinely` exists only while exactly one instance exists in that window, and never overwrites an unrelated global. `window.SplinelyRuntime.createRuntime(svg, project?, options?)` allows explicit mounting. `destroy()` unregisters the instance. Multiple inline copies share only an instance registry, not document state, listeners, audio contexts, or clocks.

Preferred data block: `<metadata id="splinely-project">XML-escaped JSON</metadata>`. `Project::to_svg(runtime_source)` in the core already emits this. Also supported: `<script id="splinely-project" type="application/json">` and an element with `data-splinely-project`. Node IDs are searched **within the owning SVG**, excluding nested SVGs; no global `getElementById`. The project block must be an SVG-namespace **direct child of the root svg** and **unique** (several candidates fail with `ambiguous-metadata`; decoys in nested SVGs/`foreignObject`/other namespaces are ignored), the same rule as `Project::from_svg_metadata` in Rust. Metadata `.textContent` must recover the original JSON. Explicit construction can instead receive an object.

### Safe embedding is the exporter's responsibility

- XML SVG metadata: XML-escape `&`, `<`, and `>` in serialized JSON. DOM textContent decodes these. JSON remains data, never executable source.
- Runtime script: wrap in CDATA and split each `]]>` as `]]]]><![CDATA[>`, or XML-escape script source. Core export already does this. Do not use JavaScript/HTML escaping in place of XML escaping.
- HTML inline JSON script: encode `<`, `>`, `&`, U+2028, U+2029 as JSON Unicode escapes (`\u003c`, etc.) before embedding to prevent a `</script>` breakout. For XML, additionally obey XML/CDATA rules; HTML raw-text script behavior differs.
- Render nodes statically at time zero before embedding scripts. Disabled scripting, `<img>` embedding, restrictive CSP, or a failed initialization leaves that fallback visible. The runtime does not bypass CSP.
- `customJs` and `rawSvg` are retained as data and **not evaluated/injected**. Exporters may add separate **trusted** scripts using `svg.splinely`; arbitrary project JavaScript is not auto-executed. Importing or previewing untrusted scripts requires host isolation.

## Canonical core schema (version 1)

All names are the camelCase serialized Rust names, not Rust field identifiers:

- `nodes[]`: `{id,kind,transform,style,boneId?}`. `locked` and `originalKind` are preserved as inert metadata: they do not block runtime patches or inject original geometry. Supported exported rect/circle/text geometry is already in DOM. Runtime writes `radius → r`, `fontSize → font-size`, `strokeWidth → stroke-width`. `x,y,rotation,scaleX,scaleY` compose a transform (x/y are translation, **not geometry coordinates**). Fill/stroke color channels 0..1 become RGB plus separate alpha.
- `bones[]` (optional, defaults empty): `{id,parentId?,x,y,rotation,length}`. Root x/y are scene coordinates; child x/y are offsets from the **parent tip**, rotated by the parent's world angle. Child rotation is relative, in degrees. Length must be positive and finite. Bone IDs share the project ID namespace. Missing parents/attachments, duplicate IDs, cycles, depth above 128 (root counts as 1), nonfinite values and FK overflow reject explicit construction; auto-mount reports the error and retains static SVG. Bones are not visible geometry and need no SVG element.
- `groups[]` (optional): `{id,name?,parentId?,rig?}`. Only `rig` affects the runtime: `{moveBone,turnBone,attachBone}` names existing bones chained move → turn → attach (otherwise construction fails). Clips and states store group animation on those bones; `set(groupId,…)` maps `x`/`y` to `moveBone` and `rotation` to `turnBone` (other properties reject like bone patches, `null` clears both). A group without a rig rejects `set`.
- `clips[]`: `{id,duration,looping,autoplay,blendMode?,weight?,tracks:[{nodeId,property,keyframes:[{time,value,easing}]}]}`. Seconds. Values `{type:"number",value:n}` or `{type:"color",value:{r,g,b,a}}`. Easing `{type:"linear"}`, `{type:"step"}`, `{type:"cubicBezier",x1,y1,x2,y2}`; easing belongs to the outgoing interval. sRGB component interpolation; before/after keys hold endpoints. Cubic solver uses 60 deterministic bisections.
- `stateMachines[]`: `{id,initial,states:[{id,onEnter,overrides:[{nodeId,property,value}]}],transitions:[{from,to,event:{name,target?},guard?:{variable,equals},actions}]}`. First matching transition wins. Guards compare JSON structurally. Variables are shared within one SVG (core `MachineInstance` snapshots are host-coordinated). Assignments preserve declared scalar types.
- Limits (the same numbers as `splinely_document` validation, so a file valid in Rust loads in the browser): clip `duration` at least 0.001 s; motion paths at most 100,000 sampled chords (64 per segment, zero-length ones included, independent of the transform) per sampled path and at most 100,000 summed over the distinct source paths (each source's static `d` plus every `d` keyframe and state override targeting it), see [motion paths](docs/motion-paths.md). Real assets: shortest clip 0.2 s, no motion paths.
- Core action tags: `setProperty`, `playClip`, `stopClip`, `blendClip`, `setVariable`, `emit`, `playAudio`, with the corresponding camelCase fields (`nodeId`, `clipId`, `assetId`, etc.). No arbitrary string guards or code actions.
- `audioAssets[]`: `{id,mimeType,dataBase64}`. Embedded base64 only; URL assets are rejected, never fetched. `audioCues[]`: `{id,assetId,time,offset,duration?,volume}` use **global timeline seconds**, not first-clip time; they work without clips and do not repeat when a clip loops.

The adapter additionally accepts ID-keyed collections, `machines`, `assets`, `loop`, `target`, `properties`, untagged numbers, numeric arrays, hex colors, string easings, state `entry`/`exit`, state-local transitions, and clip-local `audioCues`. These extensions are not the Rust project schema. See README for action aliases. Unsupported features produce diagnostics; no external resources or code are executed.

### Weighted blending (schema 1, additive fields)

Clips default to `blendMode:"override"`, `weight:1`. The other mode is `"weighted"`; weights must be finite numbers in [0,1], including on inactive clips. Unknown modes and invalid weights reject construction. Weighted keyframes must be numeric or RGBA; legacy override tracks retain their adapter support.

Activated clips keep ascending priority/document ordering. Adjacent weighted clips form a group; an override clip flushes the group, then applies legacy replacement semantics. For each target/property independently, let B be its pre-group value, S the sum of contributing weights, and D=max(1,S). The result is `B*max(0,1-S) + sum(sample_i*weight_i/D)`. Sparse channels do not contribute to S. Zero contributions preserve baseline, including absent stroke; positive stroke contributions use transparent RGBA when baseline stroke is absent. RGBA channels blend independently, rotation stays numeric, and local bones blend before FK. State overrides precede clips; explicit patches remain last. Two machines are parallel state machines, not weighted groups themselves.

`{type:"blendClip",clipId,weight,duration?}` starts a linear ramp, with omitted duration defaulting to zero. Duration must be finite and nonnegative, and the referenced clip must exist and be weighted. All authored entry/exit/transition/interaction blend actions are validated before mounting. The action never implicitly activates, restarts or stops a clip. Native preview and browser runtime are separate implementations; CLI/editor exports embed this runtime source unchanged.

### Bone composition

Tracks and state overrides may use a bone ID in `nodeId`, with **only** `x`, `y`, `rotation` and numeric values (`{type:"number",value:n}` or adapter finite numbers). Rotation interpolation is ordinary numeric interpolation, not shortest-arc interpolation (350 → 10 samples 180 at halfway). Existing outgoing easing, clip ordering and transport rules are unchanged.

After base → states → clips → explicit patches, FK is solved once. For an attached node, rotate local transform x/y by the bone world angle and add the bone **root**, then add the angle to local rotation; scales and local geometry remain unchanged. Frames always start from original local data, never previously posed nodes. Export metadata must therefore retain original local transforms even when static SVG attributes are posed. Raw `transform` overrides on canonical/attached nodes are diagnosed and ignored so they cannot bypass composition. Legacy unbound adapter elements retain their raw transform support.

## Public API

DOM capture policy: click-only figures no longer automatically capture pointers (so press/hover boundaries remain normal). Capture activates for registered drag subscriptions, drag interaction bindings, or drag machine transitions. `createRuntime(...,{pointerCapture:true})` forces capture; `pointerCapture:false` disables it. Drag events still report coordinates; they do not move nodes automatically. Ancestor-ID targets are not implicitly matched: bind actual scene-node IDs or use a trusted root handler as in the owl demo.

- `splinely.on(targetId, event, handler)` or `splinely.on(event, handler)` → unsubscribe. Handler `(detail, splinely)`. `splinely.emit(event, detail?, targetId?)`. Events include pointer/keyboard/focus, drag, `clip.end`, `state.change`, `variable.change`, and custom names. `error` handlers receive `{error}`; diagnostics retains the latest 100 errors.
- `splinely.snapshot()` → detached JSON-friendly playback/clip/state/audio/diagnostic status; observational, no clock advancement or callbacks, also available after destruction. `splinely.reportError(error)` uses the existing capped Error history and `on('error', {error})` channel; rejects calls after destruction. [Beginner cookbook](docs/runtime-cookbook.md).
- `splinely.clip(id)` → `play()`, `pause()`, `seek(seconds)`, `stop()`, `time`, `playing`, `duration`, mutable `loop`, `weight`, `setWeight(weight)`, `fadeTo(weight,seconds)`. Methods chain. Weight is a getter (not a mutable project field); only weighted clips accept weight controls. `setWeight` cancels a ramp. `fadeTo` synchronizes the production clock and ramps linearly from the current weight; interruption starts from that synchronized value. Zero seconds applies immediately. Ramps progress on paused, ended and inactive clips without activating them; fade-to-zero does not stop playback. Stop cancels the ramp while retaining weight; seek changes only sample time, preserving fade progress. Project JSON remains unchanged, and visual weights never change audio volume. Loop seeks modulo duration; nonloops clamp; negative local seeks clamp to zero. Pause holds sampled values; stop removes that clip's contribution.
- `splinely.timeline`: global `time`, `playing`, `play()`, `pause()`, `seek(seconds)`, `at(seconds, handler, {clip?: id}) → unsubscribe`. Default callback clock is the global timeline. Explicit timeline play is independent of clips. A clip play starts the global clock implicitly; pausing all clips stops an implicitly started clock. Natural clip end does not terminate global cues. Timeline pause pauses all clips; timeline seek silently synchronizes activated clips and schedules overlapping global/local audio when playing. Use clip-local seek for independent clips.
- Time callback rule: `(oldTime,newTime]`; zero fires on play from zero and each clip loop. Duration callbacks precede next-loop zero callbacks. Pausing or seeking never invokes callbacks. Backward seek rearms future crossings. Timeline events and ramp completion are segmented chronologically. All ramps advance before rendering and callbacks at each boundary, so a callback starting a clip or ramp affects only the remaining elapsed time. Duration callbacks precede `clip.end`; an end-triggered fade consumes the remaining tick delta. Loop-zero callbacks see the reset pose at the current weight. External sends/broadcasts synchronize the production clock before event processing, so catch-up end events run at their own boundaries rather than after the new event's actions. Equal-time ties: global timeline then clips in document order, callbacks in registration order. Limits: 10,000 chronological segments per tick, and 20,000 units of catch-up work per tick (playing clips visited per segment plus actions run); on overflow playback pauses with a diagnostic. Catch-up is bounded: once a looping clip without callbacks would wrap 8 times in a tick (or after 8 segments), its whole laps advance arithmetically, and in-between frames are drawn only where a callback or `clip.end` observes them (at most 64 per tick, plus the final frame).
- `splinely.machine(id).send(nameOrEventObject, detail?)`, getter `state`. Event broadcasts notify subscribers first, then machines in document order; nested events/sends queue. Initial entries run once for **all** machines before draining initial emitted events. One transition per delivered event; exit → transition actions → destination entry. Immediate event drain capped at 256 items. When the cap is hit on 3 consecutive ticks (e.g. `after: 0` timers restarting an `emit` ping-pong every frame), the machines that kept transitioning stop (they ignore further events and timers) with the diagnostic `State machine <id> stopped: event cycle limit exceeded on 3 consecutive ticks`. Repeated identical `announce` texts share one pending live-region timer.
- `splinely.bones()` returns copies of current solved poses in bone document order: `{id,x,y,rotation,length,tipX,tipY}` (world coordinates and degrees). Returns `[]` for old documents without bones; throws after destroy. Runtime bone FK overflow emits a diagnostic and retains the last valid bone poses and DOM frame until patches are corrected/cleared.
- `splinely.set(nodeId, properties)` adds explicit overrides; `set(nodeId,null)` clears. Bone IDs also work without DOM elements: `splinely.set('arm',{x:10,y:20,rotation:45})`; so do rigged group IDs (`splinely.set('group-1',{y:-20,rotation:15})`); `splinely.set('arm',null)` restores state/clip/base contributions. Bone patches reject nonnumeric values, wrong value tags, nonfinite numbers and any property outside x/y/rotation before mutation; action failures enter diagnostics. Priority: base → machine states → activated clips (ascending adapter priority, then document order) → explicit overrides. `splinely.variable(name).get()/set(value)`.
- `splinely.audio.unlock()` asynchronously creates/resumes its AudioContext and decodes assets. Call from trusted user interaction; await completion. `audio.play(assetId,{offset?,volume?,duration?})` returns `{stop(),stopped}`; it is independent of clips. `audio.pause()` stops independent sounds. `audio.seek(seconds)` stops independent sounds and seeks the global timeline (omitted seconds just stops independent sounds). Clip/timeline controls manage scheduled cue sources; paused seeks never play sounds.
- Audio pauses stop sources; resume/seek restart overlapping cues at adjusted asset offsets, without replaying completed cues. One-shot cues schedule on the AudioContext clock in advance. Native padded looping buffers repeat clip-local cues even when render frames stop; loop padding is capped at 128 MiB total per instance. Production transport follows the running audio clock; RAF and a 25ms timer share one clock anchor, avoiding double advancement. The timer also progresses ramp-only work without unlocked audio, including when RAF is suspended/unavailable; destruction clears it. On audio-clock suspension it falls back to wall-clock animation. Nonstandard AudioContext shims without `createBuffer` have only one-loop lookahead and cannot guarantee stall-free loop audio.
- `splinely.tick(deltaSeconds)` deterministic manual advancement; mount with `{autoTick:false}` when driving it yourself. `splinely.destroy()` releases listeners, pointer capture, frame/timer work, buffers/sources and AudioContext. Explicit API lookup errors throw; handler/action failures emit diagnostics without bringing down the runtime.
- Auto-tick frame loop: `createRuntime(svg, project, {maxFps: 30})` caps how often a `requestAnimationFrame` callback actually ticks: one tick per slot `floor((frameTime + 1 ms)/(1000/maxFps))` of the rAF timestamp, a grid shared by every runtime in the window, so throttled graphics all tick in the same frames (the next tick covers the elapsed time). Omit it for display rate; non-positive or non-numeric values throw. When nothing animates — no playing or fading clip, no state fade, followers at rest, no queued events, no plugin `onFrame` hook, no timeline audio cues — the loop stops requesting frames. It wakes on any API call, DOM event on the figure, or shortly before the next timed (`after`) transition or timeline callback is due, and first catches the clock up so animation resumes exactly as if it had kept ticking. An idle mascot therefore costs no per-frame JavaScript.
- Native animations (Web Animations offload): with the auto-tick loop, clip tracks that only move `x`, `y`, `rotation`, `scaleX`, `scaleY` or `opacity` of core shapes, or `x`/`y`/`rotation` of bones, run as `element.animate()` animations (keyframes with the clip's linear/step/cubic-Bézier easing, `iterations: Infinity` for loops, `composite: 'add'`/`'accumulate'` for additive clips and bone chains) so the browser composites them and JavaScript does no per-frame work for them. The runtime keeps the clip clock: `clip(id).time`, `timeline.time`, `snapshot()`, `play/pause/seek/stop`, `loop`, time callbacks and `clip.end` behave exactly as before, and animations are re-synchronised (`startTime`/`currentTime`) whenever a clip is played, paused, seeked, stopped or (un)hidden. Offload is per property and conservative: a node (or a whole bone tree) falls back to the JavaScript path while anything else contributes to the same property — a state-machine state or crossfade, `set()`, followers, motion paths, a weighted clip, a clip being faded with `setWeight`/`fadeTo` ramps, non-numeric or unusual keyframes (duplicate/out-of-order times, opacity outside 0–1), an accessibility focus ring, or unlocked audio — and returns to native once the conflict ends. Bones bound to rotating native parents use the CSS `transform` list (one `translate() rotate()` per bone in the chain); otherwise bone poses go into the individual CSS `translate`/`rotate` properties and the node's own transform stays in the `transform` attribute. Requires `element.animate`, `CSS.supports('translate'|'rotate'|'scale')` and `KeyframeEffect.prototype.composite` (Chrome/Android WebView 112+ and current Safari/Firefox); otherwise, without `requestAnimationFrame` or with `autoTick:false`, everything runs in JavaScript as before. Opt out with `createRuntime(svg, project, {nativeAnimations: false})`. While animations are offloaded the frame loop sleeps (see below) and only wakes for timers, `after` transitions, clip ends, callbacks and input. `destroy()` cancels the animations and leaves the current pose in the attributes. `splinely.bones()` still returns the true current poses.
- Visibility: by default the frame loop and native animations pause while the figure is offscreen (`IntersectionObserver`) or the document is hidden (`visibilitychange`); clocks keep running, so on return the figure shows exactly the pose it would have had (no catch-up animation). While hidden, state-machine `after` transitions, timeline callbacks and `clip.end` still fire on time from timers (not frames), and API calls work as usual. Disable with `{pauseWhenHidden: false}`.
- Shared frame loop: all runtimes in one window share a single `requestAnimationFrame` callback (module-level scheduler); each still honours its own `maxFps` and idle sleep, and destroying one does not affect the others. The 25 ms timer used for audio cues and weight ramps only runs while one of those is active.
- `splinely.use(plugin, meta?)`, `splinely.plugins()`, `createRuntime(svg, project, {plugins:[plugin]})`: **opt-in** runtime plugins, API version `1` (`SplinelyRuntime.PLUGIN_API_VERSION`). A plugin is `{id, apiVersion:1, events?, frameBudgetMs?, setup(ctx), onEvent(event, ctx), onState(change, ctx), onFrame(frame, ctx)}`; unknown keys, wrong `apiVersion`, duplicate ids or more than 8 plugins are reported as diagnostics (not thrown). Event/state/frame payloads are frozen primitive copies; `ctx` (emit, getVariable/setVariable, send, playClip/stopClip, set, snapshot, report, onDestroy) delegates to the public API so the same validation applies. Hook exceptions become diagnostics, 5 errors or 3 `onFrame` budget overruns (default 4 ms, measured after the call) disable the plugin. Without plugins there is no subscription and only one `null` check per tick. Plugins are never read from project data; the CLI embeds them only with `export --plugin … --trusted-js`. **Not a sandbox** – see `docs/plugins.md`.

## Verification

```sh
node --check runtime/src/splinely.js
node --test runtime/tests/*.test.cjs crates/splinely_cli/tests/*.test.cjs
node runtime/tests/build-browser-smoke.cjs
```

Weighted tests cover residual/midpoint/overweight normalization, sparse channels, override boundaries, states and explicit patches, RGBA/absent stroke, pre-FK bone blending, immutable defaults, invalid weights/actions, interrupted/paused/ended ramps, stop/seek rules, segmented partition parity, duration-before-end return fades with leftover elapsed time, production send/broadcast catch-up ordering, loop-zero rendered poses, duration-callback restart suppression of stale end events, parallel scroll/jump behavior and ramp-only production timer cleanup. Legacy bone tests cover child-first hierarchy, parent tips, local attachment/geometry/scales, numeric rotation and easing, state/clip/explicit composition, pause/seek/loop transport, typed allowlists, invalid rigs and depth boundaries, overflow recovery, inert node metadata, old no-bones projects, nested SVG scoping and destruction during error reporting. The generated direct-file SVG smoke additionally checks bone hierarchy, attachment and numeric rotation interpolation in a real browser; see `runtime/README.md` for opening/screenshot instructions.

No guarantees of arbitrary SVG morphing, additive blending, audio codec availability, sample-perfect visual/audio synchronization, device latency, offline voices, or execution inside image-only SVG contexts. Node tests use fake audio; direct Firefox SVG smoke verifies script execution, XML embedding, DOM events, sampling, loops, and scoping, not physical audio output.
